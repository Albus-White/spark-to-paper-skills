## 可直接发布的正文

Spark-to-Paper 最近做了一次很大的更新。我们想解决的问题很直接：能不能让 Agent 真正参与科研？自己查资料、提出可以验证的假设、设计并跑完实验，再根据真实结果决定哪条路值得继续、哪条路应该放弃。最后交出来的论文要有证据、有结果，也应该有机会带来新的发现。

这就是我们一直在做的 **Spark-to-Paper**。

它把研究流程拆成 **1 个调度器和 13 个可以单独调用的 Skills**：整理想法、找文献、定实验、跑实验、根据结果修改结论、画图、审稿、检查引用和数字，最后编译出完整论文。你可以让整套流程从头跑到尾，也可以只叫其中一个来帮忙。

整套流程始终把证据放在文字前面：**实验没有跑出来，数字就不能写进论文；真实结果不支持，结论就必须跟着改。** Agent 可以大胆提出假设，但不能靠想象补结果。它会通过真实实验寻找新的证据，尝试做出有实际影响、有科研贡献的发现。

这次更新，我们还认真重做了最让人头疼的画图环节。实验结果图直接读取真实数据；方法图和架构图先出候选，再按论文事实重绘成可编辑 SVG。画完以后继续量、继续修，一直迭代到满意。最终会保留 PNG 预览、SVG 源文件和 vector PDF，放大不糊，颜色、字号和排版也都能继续改。

文献有没有漏，论点和引用能不能对上，数字能不能找到来源，实验结果和结论有没有打架，也都会继续检查。需要理解和判断的地方交给 Agent，能用代码查清楚的地方就让代码把关。

更重要的是，这套流程不是写死的。每次运行留下的实验记录、失败路线、审稿意见和有效做法，都可以沉淀进知识图谱与经验规则。做下一项研究时，它不必把走过的弯路再走一遍；用得越多，积累的研究经验越丰富，整套工作流也会在真实任务里继续进化。

项目已经开源，代码、论文样例和安装方式都放在 GitHub。平时需要写论文、跑实验、改图，或者只是想看看这套流程现在能做到什么，都欢迎来试，也欢迎提 issue。
